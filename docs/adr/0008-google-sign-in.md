# 0008: Google Sign-In replaces the verification code — ownership via Google Workspace

Discovery: `umindanao.edu.ph` runs Google Workspace (MX → `aspmx.l.google.com`; SPF includes `_spf.google.com`), so every UM Address is a real Google account. Google OAuth therefore proves inbox ownership cryptographically — there is no fabricated-address vector — which makes ADR 0001's emailed verification code redundant: a code only demonstrates that someone with inbox access received it, while signing into the account itself demonstrates control over the inbox with the account holder's own credentials.

Decision: **Google Sign-In is the only sign-in method for v1** (product decision; no fallback provider). The ADR 0001 email/password + emailed-code flow is dropped, which also removes the project's would-be need for an email-sending service. The format gate is retained exactly: the chosen address must match `initial.surname.######@umindanao.edu.ph` (6-digit ID segment excludes staff and alumni). Enforcement happens in-app the moment Google returns the account and **before any Firebase session is created** — non-matching accounts are signed out locally and refused with a clear message. `hostedDomain: umindanao.edu.ph` narrows the Google account chooser where the platform supports it, but the format check remains the authoritative gate because Firebase has no console-side domain restriction for the Google provider.

**Considered options (rejected):** keeping both providers (two code paths and the emailed-code machinery — including an email-sending dependency — for no pilot-scale gain); server-side `hd`-claim verification via Cloud Functions (Blaze-plan billing for no added security at pilot scale, since the Google-issued token already makes the client-side check non-spoofable — revisit as hardening later).

**Consequences:** auth setup requires the Google provider enabled in the Auth console and the signing keystore's SHA-1 registered on the Android app (debug + later release/Play keys). Members are UM's Workspace users, so the gate's reach equals the university's Workspace coverage — if UM ever leaves Workspace, Google Sign-In breaks and ADR 0001's code flow is the documented fallback. PII handling is unchanged (ADR 0007): the 6-digit ID is never displayed, and profiles derive a display name from initial + surname.

**Supersedes:** [ADR 0001](0001-student-email-gate.md) — the ownership mechanism (verification code) only; the format gate and its rationale stand verbatim.
